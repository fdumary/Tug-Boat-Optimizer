# Quantum pipeline fixes (2026-10-17)

Follows the code review of commit `0bfe473`. Each fix lists cause, change and evidence.
Baseline is `main` at `ab551bb`. All runs: Python 3.13, qiskit 2.6.0, qiskit-ibm-runtime 0.50.0,
qiskit-aer, dimod 0.12.22, on Linux.

## Before / after, 4 tugs, wind 12 kn (`scripts/run_quantum_optimizer.py --tugs 4 --wind 12`)

| | Best answer reported | Energy | True optimum |
|---|---|---|---|
| Before | 1 tug on the contract container, both spot ships rejected | +500 | −9,000 |
| After | contract container + both spot ships, 3 tugs | −9,000 | −9,000 |
| After, `--no-qec` | same | −9,000 | −9,000 |

Wind 22 kn finds the optimum (+1,500, spot ships rejected) both before and after.

## 1. IBM hardware path crashed (`scripts/run_quantum_optimizer.py`)

Cause, found by running the branch against `FakeBrisbane` (127-qubit IBM noise model):
- `channel="ibm_quantum"`: `ValueError: 'channel' can only be 'ibm_cloud', or 'ibm_quantum_platform'`.
- Circuit had no measurements: `AttributeError: 'DataBin' object has no attribute 'meas'`.
- `sampler.options.resilience_level` exists only on EstimatorV2: `ValidationError ... no attribute 'resilience_level'`.
- Angle binding hard-coded p=1.

Change: `channel="ibm_quantum_platform"`; `bound_qc.measure_all()`; dynamical decoupling plus gate
and measurement twirling instead of `resilience_level`; `QAOASimulator.bind_parameters()` binds any p;
new `--p` flag.

Evidence: the real `solve_tug_scheduling_quantum(..., ibm_token=...)` was run with
`QiskitRuntimeService` stubbed to return `FakeBrisbane`. It completes for T=2 (10 qubits,
transpiled depth 219) and T=3 (14 qubits, depth 351) and returns the optimum (−4,500 and −9,000).
Not yet run on a real IBM QPU (needs a token).

## 2. Answer taken from the most frequent bitstrings (`qaoa_mapper.py`, `run_quantum_optimizer.py`)

Cause: the script kept the 10 most likely bitstrings. The optimum is spread over many equivalent
bitstrings (tugs are interchangeable), so it rarely appears among them.

Change: new `rank_samples_by_energy()` scores every measured bitstring by QUBO energy and returns
lowest first. Hardware and local runs both use it; the local run now draws shots from the
statevector (`QAOASimulator.sample_counts`) so it behaves like hardware.

## 3. QEC syndrome check flagged valid answers (`error_mitigation.py`)

Cause: `sum(... for s in self.tugs)` iterated tugs as `s` with a stale `t`, so per-ship tug counts
were wrong; the exact optimum was reported as `phantom_spot_error` and `unmet_contract_error`.
Repair also never removed surplus tugs from a contract ship, and repaired results were not re-ranked.

Change: iterate `for t in self.tugs`; release surplus contract tugs; sort results by energy.

## 4. Benchmark energy and overlap were wrong (`scripts/run_qaoa_benchmark.py`, `results/`)

Cause: `(value − sim.offset) × norm + bqm.offset` dropped the Ising constant, giving expected
energies below the ground state (approximation ratio 1.19, impossible). "Ground state overlap" only
looked at the top 10 bitstrings after QEC repair.

Change: `raw = value × norm_factor`; overlap is now the total probability on all optimal states
from the full statevector. `results/` regenerated.

New results (approximation ratio, overlap with optimal states):

| Scenario | p=1 | p=2 |
|---|---|---|
| Calm 10 kn | 0.79, 0.00% | 0.93, 3.06% |
| Windy 22 kn | 0.84, 0.00% | 0.83, 0.00% |

Calm p=1 is low because COBYLA from the benchmark's fixed seed (123) lands in a poor local
minimum; seeds 1-3 with 60 iterations reach 3.0% (see penalty sweep below). Multi-start was not added.

## 5. Penalty weights (`qubo_builder.py`)

Cause: fixed penalties of 15k-40k against a tug cost of 500 mean the cost signal is under 1% of the
Hamiltonian scale after normalisation.

Change: penalties left unset default to 2 × (largest spot revenue + largest tug cost), 12,000 for
the demo instance. Explicit values still override.

Evidence (penalty sweep, 150 random instances, 1-4 tugs, 2-3 ships, mixed wind and crew rest,
both pre-filter modes):
- Exact QUBO minimum equals the true constrained optimum in all 150 with the new default.
  A flat 7,000 failed 3, so the safety factor matters.
- Normalisation factor 75,250 → 33,250. QAOA p=1 P(optimal), T=4: calm 2.3% → 3.0%,
  windy unchanged at 0.3%. A modest gain.
- `scripts/test_qubo.py`: same energies and spot decisions in all 3 scenarios as before
  (tug labels can differ, as tugs are interchangeable).

## Not changed
- QEC is still classical post-processing, not quantum error correction.
- `ReadoutErrorMitigator` is still unused.
- The model still has no time dimension.
